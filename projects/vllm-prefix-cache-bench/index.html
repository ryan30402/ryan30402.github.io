01 / THE QUESTION

When does reusing a prefix pay off?

Repeated system prompts and documents can create reusable computation. This study isolates a controlled, shared-prefix workload rather than assuming every request benefits equally.

Token-controlled inputs. vLLM supplies the prefix-cache implementation; this project supplies the experiment and measurement tooling.

THREE OBSERVATIONS

The workload determines the gain.

At a 2,048-token prefix and concurrency 32, throughput increases from 271.2 to 756.3 output tokens/s.

The no-prefix control stays near 1×.

At concurrency 32 without a shared prefix, throughput is 832.2 versus 831.8 tokens/s. There is no meaningful throughput gain in that condition.

Latency needs context.

The initial closed-loop burst contributes to tail TTFT. End-to-end latency here excludes waiting in the client-side concurrency queue.

03 / WHAT I BUILT

More than a cache toggle.

The engineering contribution is a controlled benchmark harness: generating inputs, orchestrating paired experiments, and reconciling client measurements with server counters.

01

Controlled workloads

Exact token counts, shared prefix tokens, and disjoint warm-up and measured suffixes. Prefix length and concurrency are explicit test conditions.

02

Paired experiments

Fresh server processes, readiness checks, warm-up, and cache-off/cache-on pairs with randomized order. Per-run settings and environment records remain available.

03

Evidence and checks

Per-request timing, Prometheus counter differences, request-count checks, failure records, and CPU tests for the harness. Measurement and analysis are inspectable separately.

  1. StartFresh vLLM service
  2. Warm up50 requests
  3. SnapshotCounter baseline
  4. Measure500 requests
  5. ValidateCounter delta = 500

A cleaner measurement boundary

Warm-up and measured requests share the intended prefix but not a complete prompt. Counter deltas start after warm-up, so they cover the same 500 requests as the benchmark results. The repository keeps the earlier exploratory sweep separate; it is not pooled into these reference numbers.

04 / SCOPE & EVIDENCE

Useful measurements. Clear boundaries.

What this study supports

Serving-level comparisons for Qwen2.5-7B-Instruct in BF16 on one NVIDIA A40 GPU model, with vLLM 0.33.0. The 42 reference runs include 36 core runs and six memory-pressure runs.

The code, fixed configurations, raw request records, and analysis are available in the repository. The numbers on this page are tied to a specific source revision.

Source: 31bd3f2

What it does not establish

Traffic is synthetic: one shared prefix, random-token suffixes, fixed output length, and closed-loop concurrency. This is not a production traffic trace or an open-loop capacity study.

Output sequences can differ between cache states; exact-match checks do not establish equal answer quality. The project evaluates existing vLLM behavior, not a new cache algorithm or custom GPU kernel.

Multiple-prefix traffic, SLO-guided configuration selection, and cross-hardware validation remain separate extensions, not reported accomplishments.
